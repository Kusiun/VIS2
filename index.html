Классификация информационных систем

Ниже приведена классификация трёх проектов, объяснение выбора архитектуры и подходящие технологии.

1. Таблица классификации

Проект Масштаб Уровень Архитектура
«ЭкоЕда» Локальная TPS Веб-ориентированная
«МедГрад» Корпоративная TPS, MIS, DSS Веб-ориентированная
«СкиллБиржа» Глобальная TPS, DSS Веб-ориентированная

2. Кейс «ЭкоЕда»

Масштаб: локальная система, так как магазин работает в одном городе.

Уровень: TPS — система обрабатывает обычные операции: просмотр товаров и оформление заказов.

Архитектура: веб-ориентированная. Покупатели заходят на сайт через браузер, а заказы отправляются администратору на email. Это недорого и удобно для небольшого магазина.

Технологии:
  • HTML — создание страниц сайта.
  • CSS — внешний вид сайта.
  • JavaScript — корзина, подсчёт стоимости и отправка формы заказа.

3. Кейс «МедГрад»

Масштаб: корпоративная система, потому что объединяет 10 филиалов и много сотрудников.

Уровень: TPS — запись пациентов и ведение карт; MIS — отчёты о работе клиник; DSS — аналитика для главврача.

Архитектура: веб-ориентированная. Все филиалы работают с общей системой через интернет. Данные хранятся централизованно, поэтому сотрудники видят актуальную информацию.

Технологии:
  • HTML и CSS — страницы для пациентов и сотрудников.
  • JavaScript — запись на приём, расписание, чат и работа с сервером.
  • Python — обработка данных и создание аналитических отчётов.

Так как система хранит медицинские данные, необходимо защитить информацию и ограничить доступ к ней.

4. Кейс «СкиллБиржа»

Масштаб: глобальная система, так как пользователи будут работать из разных стран.

Уровень: TPS — регистрация, поиск заказов, чат и сделки; DSS — анализ рейтингов и подозрительных действий.

Архитектура: веб-ориентированная. Пользователи работают через браузер. Систему можно расширять, чтобы она выдерживала большое количество одновременных подключений.

Технологии:
  • HTML и CSS — оформление сайта и личных кабинетов.
  • JavaScript — поиск заказов, чат, регистрация и обработка сделок.
  • Python — анализ данных и рейтингов пользователей.
  • C++ — при необходимости для ускорения отдельных сложных операций.

Для безопасных сделок нужны проверка пользователей, защита данных и надёжная обработка платежей. Платежи лучше проводить через специальный платёжный сервис.

5. Вывод

  • «ЭкоЕда» — простая локальная система для приёма заказов.
  • «МедГрад» — корпоративная система для работы филиалов и анализа их деятельности.
  • «СкиллБиржа» — международная платформа, рассчитанная на большое количество пользователей.

Почему во всех случаях веб-архитектура? Все три проекта предполагают работу через сайт или браузер. При этом сложность серверной части будет разной: от простой формы заказа до большой распределённой платформы.
