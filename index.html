ПР №1. Классификация информационных систем

Кейс 1. Фермерский кооператив «ЭкоЕда»

Масштаб: локальная (магазин, 3-5 сотрудников, один город)

Уровень управления: TPS (транзакционная обработка заказов)

Архитектура: веб-ориентированная

Обоснование: минимальный бюджет, нужен только сайт-витрина с корзиной и отправкой заказа на email. Веб-архитектура даёт доступ с любого устройства без установки.

Стек: HTML/CSS (вёрстка), JavaScript (корзина, валидация), Python (Flask — приём заказа, отправка email). C++ не требуется.

Кейс 2. Сеть клиник «МедГрад»

Масштаб: корпоративная (10 филиалов, 500+ сотрудников)

Уровень управления: MIS + DSS (запись, карты, расписание, аналитика)

Архитектура: клиент-серверная (трёхзвенная)

Обоснование: нужна централизованная БД с картами пациентов, разграничение прав, онлайн-консультации и аналитика. Клиент-серверная архитектура даёт целостность данных и масштабируемость.

Стек: HTML/CSS/JavaScript (React SPA), Python (FastAPI/Django — API, бизнес-логика), C++ (быстрая аналитика и проверка пересечений расписания).

Кейс 3. Фриланс-биржа «СкиллБиржа»

Масштаб: глобальная (международный сервис, тысячи пользователей одновременно)

Уровень управления: TPS + MIS + DSS (сделки, рейтинги, эскроу, аналитика)

Архитектура: веб-ориентированная (микросервисы + SPA)

Обоснование: высокие требования к скорости, безопасности, доступности 24/7. Веб-ориентированная архитектура с горизонтальным масштабированием — единственный вариант для глобальной биржи.

Стек: HTML/CSS/JavaScript (React/Next.js), Python (FastAPI — микросервисы пользователей, заказов, эскроу), C++ (высоконагруженный поиск, обработка очередей).

ПР №2. Моделирование процессов «Книжный склад»

1. Процесс AS-IS

Роли: клиент, менеджер, бухгалтер, курьер.

  • Шаги: звонок → ручная проверка наличия → счёт в Excel → email → оплата → квитанция → сверка в банк-клиенте → сборка → вызов курьера.
  • Точки задержки: ожидание менеджера, ручной поиск книг, ручная сверка оплаты, задержка курьера.
  • Дублирование данных: список книг диктуется голосом и вручную вносится в Excel; квитанция обрабатывается и в бухгалтерии, и в банк-клиенте.

2. Процесс TO-BE

  • Клиент сам: выбирает книги в каталоге, оформляет и оплачивает заказ онлайн, отслеживает статус.
  • Автоматизируется: проверка остатков, формирование счёта, приём оплаты через платёжный шлюз, уведомления по email, передача на сборку.
  • Исключается дублирование: данные о заказе и оплате вводятся один раз и хранятся в единой БД; бухгалтерия получает автоматический отчёт.

3. Постановка задачи (ТЗ)

Публичная часть (HTML/JS/React): каталог с поиском и корзиной, оформление заказа, онлайн-оплата, личный кабинет.

Админ-панель (Python/Node.js): управление товарами и остатками, обработка заказов, отчёты, роли менеджера и бухгалтера.

C++ модуль: складской учёт — быстрая обработка остатков и резервирование при одновременных заказах.

Интеграции: email, платёжный шлюз, банк-клиент.

БД → Flask: OK Flask → React: 201 Created {занятие} Flask → Email: уведомление преподавателю end

Механизм синхронизации

Локально хранится: расписание врачей, записи пациентов, электронные карты, справочники.

Разрешение конфликтов: стратегия «последняя запись выигрывает» по времени изменения (updated_at). Для слотов записи проверка на центральном сервере: если слот уже занят, локальная запись помечается конфликтной и врачу отправляется уведомление для ручного разрешения.

4. C++ модуль проверки конфликтов

#include <vector>
using namespace std;

class ScheduleOptimizer {
public:
    bool hasConflict(const ScheduleItem& newItem,
                     const vector<ScheduleItem>& existing) const {
        for (const auto& item : existing) {
            if (item.id == newItem.id) continue;
            if (item.day != newItem.day) continue;

            bool timeOverlap = !(newItem.end <= item.start ||
                                 newItem.start >= item.end);
            if (!timeOverlap) continue;

            if (item.teacherId == newItem.teacherId ||
                item.roomId == newItem.roomId ||
                item.groupId == newItem.groupId) {
                return true;
            }
        }
        return false;
    }
};

5. Вызов C++ из Python

Фрагмент бэкенда (Python + Flask + ctypes)

import ctypes
from flask import Flask, request, jsonify

app = Flask(__name__)

lib = ctypes.CDLL('./libschedule.so')

@app.route('/api/schedule', methods=['POST'])
def add_schedule():
    data = request.json
    if not all(k in data for k in ('group_id', 'teacher_id', 'room_id')):
        return jsonify({'error': 'Не все поля заполнены'}), 400

    has_conflict = lib.has_conflict(...)
    if has_conflict:
        return jsonify({'error': 'Конфликт в расписании'}), 409

    return jsonify({'status': 'created'}), 201

if __name__ == '__main__':
    app.run(debug=True)
